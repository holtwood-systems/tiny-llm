## 4. 瓶颈结论（Top 3，本机）

1. **w8a16 M=1 matmul 仍是主瓶颈**（≈46% kernel 估算）：GEMV 形状并行度
   受限；单 kernel 3–11 µs 已逼近本机小规模 launch 下沿，继续优化
   收益空间取决于减少调用次数（融合）而非单 kernel 提速。
2. **LM head 带宽墙**：282 µs 读 ~272 MB fp16 → ~966 GB/s 有效带宽，
   接近 RTX 4090 GDDR6X ~1008 GB/s 峰值——同 3060 结论，已达上限。
3. **elementwise 长尾占比升至 26%**：单个 kernel 已 2–3 µs（launch 下限），
   合计被调用次数放大；收益方向是融合（rmsnorm+add、rope+append 等），
   这也正是 CUDA Graphs 在 4090 上仍有 -10.4% TPOT 的原因。

## 6. 复现核对 / 限制

- [x] 命令可原样执行；数字与原始日志/JSON 一致；硬件+commit+模型哈希已绑
- **ncu/nsys 不可用**：`ERR_NVGPUCTRPERM`（驱动 RestrictProfilingToAdminUsers，
  容器内不可改，需宿主机降权）。kernel 分布改用 `tiny_llm_kernel_bench`
  的 cudaEvent 实测，无 SM/DRAM 利用率数据——「带宽墙」结论由
  282 µs×272 MB ≈ 966 GB/s 与峰值 1008 GB/s 的比值支撑，非 counter 直读。
- TPOT 为同机 A/B（graphs on/off）；单机单卡单架构 sm_89。
- decode 64 token、prompt 1 token、greedy；batch=1。
- 运行时段 GPU 无其他进程占用（nvidia-smi 确认 <5 MiB）。
